# Internal security review of v3, 2026-10-01

Scope: what v3 added over v2, `git diff v0.8.0..v3-contracts -- contracts/src stylus/pricer/src` (1,354 lines): the EIP-712 signer consent in `AgentRegistry`, the fee high-water mark in `FeeManager`, the active-agent rule and the `SeriesRisk` call in `EpochManager`, `InvalidMandate(reason)`, `RiskLens`, `RiskLib` and the Stylus risk engine (`stylus/pricer/src/risk.rs`), plus `DecisionLog` (on `main`, deployed next to every deployment) and the places where v3 touches v2 assumptions (settlement, compensation, unbonding). Checked against [design.md §11](../design.md), [threat-model.md](../threat-model.md), [audit-readiness.md](../audit-readiness.md) and decisions D31–D37. Method as in the [v2 review](review-2026-09-29.md): an adversarial read, attack hypotheses, and a Foundry test for every claim; a finding counts only with a test that shows it.

v3 is live on Robinhood Chain testnet (46630) and Arbitrum Sepolia (421614) and will not be redeployed before 4 October, so the fixes live on the `v3-contracts` branch and the deployed code keeps the behaviour described under each finding. None of the findings puts funds at risk: no High, no Medium.

The external interface changed in two places: `AgentRegistry` gained `revokeConsents()` and the event `ConsentsRevoked`, and `EpochManager.openEpoch` can now revert `AgentNotActive`. `RiskLens` keeps its ABI; only its values for closed series changed. `DecisionLog.sol` was copied onto the branch, byte for byte, so that its test runs there.

**Operational note for the lead.** On both live v3 deployments agent #1 holds exactly `minBond` (50 USDG, after one 10 USDG slash) with 1 strike. One more rejected proposal takes its bond to 40 USDG and makes it inactive: with the deployed code its Monday `openEpoch` would still lock the vault for a day with no proposal possible (L-03); with the fix it reverts at once. Topping the bond up before the next epoch avoids both. None of the findings justifies a v3.1 redeployment before the deadline.

The original findings follow as reported.

Also reviewed and held, with no separate test because the existing suite already covers them:

- `InvalidMandate(reason)`: `mandateError` returns the first broken rule in the documented order and `validate` reverts with it (Halmos `MandateGuardFormal`, one unit test per code). `minDeltaBps = 0` is still allowed, as in v2.
- `registerVault` and `setVaultAgent` refuse unknown, unbonded, under-bonded, suspended and retired agents and accept an active foreign one; id 0 detaches (`EpochManager.t.sol`).
- The lens' worst payout never exceeds the locked collateral, in collateral units and in value at the shocked spot, on a −99.99% … +1000% grid (`invariant_worstCaseScenarioWithinCollateral`, `testFuzz_worstCaseWithinCollateral`), and `seriesRiskAt` at the settlement price returns exactly the payout `settle` locks up.
- `settle` is unchanged apart from `chargeFee`, which is a state write in the `FeeManager` with no call out; the `SeriesRisk` call is a `staticcall` after the state changes, under `nonReentrant`. SafeStockFeed, `StockOracle`, `abortEpoch`, `emergencyCancel`, unbonding and slashing are byte-identical to v2.

Considered and dropped as not exploitable:

- **Front-running a registration with someone else's consent.** The consent names the owner (`msg.sender`), the payout and the identity; another caller gets `InvalidConsent` and burns no nonce (`test_revert_register_consentBoundToOwnerPayoutAndIdentity`).
- **The payout and identity in the consent are not binding afterwards.** The owner can `setPayout` and `setIdentity` without the signer. By design: the consent is about the key, not the economics.
- **A signer cannot resign.** Once a consent is used the binding lasts until the owner rotates the key. The signer only ever risks being unable to sign for another agent; sign for owners you trust, and use `revokeConsents` while the consent is unused.
- **Contract signers.** Only ECDSA consents are accepted; a contract can still be a signer by calling `register` itself (documented in design.md §11).
- **`setFeeManager` resets every carry.** An admin power, documented in design.md §11; the admin cannot move funds with it.
- **Griefing the keeper's sigma through the lens.** The live view reads the protocol's own sigma and SafeStockFeed spot and reverts on an unsafe feed, so it cannot show a price the protocol would not trade at.
- **A huge `shocks` array.** `scenarioLoss` is only reached through the view functions; the caller pays its own gas.
- **`worstShock` when nothing can be lost.** The first grid point (−30%) is named with a loss of 0. Cosmetic.
