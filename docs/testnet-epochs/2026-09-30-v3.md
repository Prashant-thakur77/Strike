v3 was deployed next to the live v2 on Robinhood Chain testnet (chain id 46630) from the [`v3-contracts`](https://github.com/Prashant-thakur77/Strike/tree/v3-contracts) branch. v2 keeps running untouched until its covered-call series settles on Friday 2026-10-02 at 20:00 UTC. Addresses: [`46630-v3.json`](https://github.com/Prashant-thakur77/Strike/blob/v3-contracts/contracts/deployments/46630-v3.json) on the branch; the full table is in [DEPLOYMENTS.md](../DEPLOYMENTS.md#v3-deployed-next-to-v2-2026-09-30).

**Status: deployed, verified, agent registered, bonded, and the first live v3 epoch ran on Thursday 1 October (14:45 to 14:54 UTC, NYSE open): see [section 7](#7-live-epoch-1-october).** Claude planned the covered call and agent #1 proposed it on-chain, the contract rejected an out-of-mandate put and slashed the bond, and a separate buyer wallet bought the calls. Sections 1 to 6 are the deployment on 30 September, when the deployer held 39.994056 USDG and the epoch had to wait for testnet USDG.

## 3. Agent #1 on v3: EIP-712 signer consent and ERC-8004 #114

v2's agent #1 signs with the deployer key (self-registration). On v3 the agent has a separate signer key, `0x4fd9565bf8C0Bda9bBdF2Add233d19c64e50AC6f` (generated locally, kept in the gitignored `contracts/.env` as `AGENT_SIGNER_KEY`, the name `Seed.s.sol` reads), so registration goes through the new consent path:

1. The owner read `registerDigest(signer, owner, payout, 0, deadline)` from the registry: `0x4076407c…b32a`, domain separator `0x1747ccb3…fe43` (`Strike AgentRegistry` / `1`, chain 46630), signer nonce 0.
2. The signer key signed that digest off-chain (EIP-712 `Register`).
3. The owner (the deployer) sent `register(signer, payout = owner, erc8004Id = 0, deadline, signature)`: agent **#1**, [tx `0x52f5999d…`](https://explorer.testnet.chain.robinhood.com/tx/0x52f5999da7ab48d37ffb8fc5d3b476b9da1c0d3faa855de645cb80a784827162) (block 126,718,920, 13:58 UTC). The signer's nonce is now 1, so the same signature cannot be replayed.
4. The owner linked ERC-8004 identity **#114** (owned by the deployer on the official Identity Registry) with `setIdentity(1, 114)`: [tx `0xc617c3eb…`](https://explorer.testnet.chain.robinhood.com/tx/0xc617c3eb7feb026513bf791bb0e1c2108d4821bd86995c49a14f391832904154) (block 126,718,935).

`getAgent(1)` now returns owner `0x26b2…13Ff`, signer `0x4fd9…AC6f`, payout `0x26b2…13Ff`, status Active, 0 strikes, `erc8004Id` 114, bond 0. `isActive(1)` is **false** until 50 USDG is bonded.

The active-agent check works as designed: simulating `VaultFactory.createVault` for the TSLA put vault with agent #1 (the v2 mandate: |delta| 0.10–0.35, premium ≥ 95% of fair value, yield ≥ 0.05%, size ≤ 80%, tenor 1–8 days) reverts `AgentNotActive(1)` (`0x98a4d667…0001`). On v2 the same call would have created a vault run by an unbonded agent.

## 6. The epoch, once funded

The plan, unchanged from [cycle 9](../plans/2026-09-30-cycle9.md) step 9.3. Bond **60** USDG, as v2 did (D27): a 10 USDG slash then leaves the agent at the 50 USDG minimum and still active. With 50 USDG the rejection would drop the bond to 40, `isActive` would turn false and every later proposal would revert `AgentNotActive`. So the order is:

1. Keeper once: the TSLA MirrorFeed's last round is 2026-09-29 17:05 UTC, and `maxPriceAge` is 25 hours, so it must be refreshed first.
2. `approve` and `postBond(1, 60e6)`; `createVault` for the TSLA cash-secured put and the covered call with the v2 mandates; write `46630-v3-vaults.json`. With the agent active, `createVault` reaches the mandate check, so a simulated vault with an inverted delta band shows the new `InvalidMandate(1)` (`DeltaBandInverted`).
3. Deposit USDG in the put vault. Fractional sizes are fine: at a strike near 340 USDG, 30 USDG covers about 0.088 options, of which 80% can be sold.
4. Send the signer a little ETH for gas. The signer calls `openEpoch`, then a deliberately out-of-mandate `proposeSeries` (an at-the-money put): `ProposalRejected` with reason 8 (`DeltaOutOfBand`) and a 10 USDG slash into `compensation[vault]`. The epoch stays `Open`.
5. The signer calls `proposeByDelta(put vault, 2000, Friday 20:00 UTC, size, 10000)`: accepted, with `SeriesProposed` and the new **`SeriesRisk`** event (delta, gamma, vega, theta at the epoch's opening snapshot). Read `RiskLens.seriesRisk(seriesId)` and log it.
6. Buy a fraction of the series from the deployer.
7. Anchor this log in the v3 DecisionLog from the signer.
8. Friday after 20:00 UTC: `settle` (permissionless). The keeper's `settle_expired` reads `deployments/46630.json`, so v3 is settled with `cast send <v3 EpochManager> "settle(address,uint80)"` or the keeper pointed at `46630-v3.json`.
