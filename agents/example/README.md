# Strike example agent

A strike-picking agent that works through the [Strike MCP server](../../mcp/) and the chain's own contracts. Each propose run is a pipeline of specialists (below): a market analyst decides whether to trade at all, a risk analyst prices a ladder of strikes, a planner picks one, a critic checks it, and only then does the agent propose on-chain. The contract checks every proposal against the vault's mandate and slashes the agent's USDG bond when one falls outside it.

```bash
# from the repo root; STRIKE_AGENT_PRIVATE_KEY is the agent signer's key
STRIKE_CHAIN_ID=46630 STRIKE_AGENT_PRIVATE_KEY=0x... pnpm --filter @strike/agent-example start -- --vault sTSLA-CC
```

| Flag                           | What it does                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (none)                         | Run the specialists and propose this epoch's option at 0.20 delta (`--target-delta` to change); a no-go or a veto is a recorded no-trade (exit 0)                                                                                                                                                                                                                                                                                |
| `--profile conservative`       | A named rule instead of the default: 0.15 delta at 108% of fair value, at most half the vault's capacity. The decision record names the planner `rule: conservative` (`rule: default` otherwise)                                                                                                                                                                                                                                 |
| `--llm`                        | Claude chooses the delta and premium factor using read-only tools (API key or Claude Code, below); falls back to the default                                                                                                                                                                                                                                                                                                     |
| `--planner api\|claude-code`   | With `--llm`: force the Claude API or the Claude Code CLI                                                                                                                                                                                                                                                                                                                                                                        |
| `--dry-run`                    | Run every specialist, then stop before the contract; nothing is sent (no agent key needed). The record is named `<date>-<symbol>-dry-run` (`-claude-dry-run` when Claude planned) and says so                                                                                                                                                                                                                                    |
| `--ignore-session`             | With `--dry-run` only: evaluate as if the NYSE were open, so the stages after the market analyst run on a weekend. The record says so (`-as-if-open-dry-run`). Never allowed with a send                                                                                                                                                                                                                                         |
| `--reckless`                   | Force an at-the-money proposal to show the contract rejecting it and slashing the bond                                                                                                                                                                                                                                                                                                                                           |
| `--settle`                     | Settle the vault's expired series                                                                                                                                                                                                                                                                                                                                                                                                |
| `--status`                     | Print the vault and the agent's track record                                                                                                                                                                                                                                                                                                                                                                                     |
| `--buy`, `--hedge`, `--redeem` | Buyer side: buy options within `--budget`, hedge a holding, redeem settled options                                                                                                                                                                                                                                                                                                                                               |
| `--register`                   | Join as a new agent: dry run, then register and bond (`--bond`), optionally `--create-vault TSLA:call\|put`                                                                                                                                                                                                                                                                                                                      |
| `--log <dir>`                  | Write a decision record for a propose, `--reckless` or `--settle` run to `<dir>/<YYYY-MM-DD>-<vault symbol>.md` and `.json`                                                                                                                                                                                                                                                                                                      |
| `--anchor`                     | With `--log`: anchor each record's keccak256 hash on-chain in DecisionLog, signed by the agent's key                                                                                                                                                                                                                                                                                                                             |
| `--paid-report`                | Before a propose or `--reckless` run, buy the vault's full risk report over x402 through the MCP tool `paid_risk_report` (0.01 test USDC on Arbitrum Sepolia or USDG on Robinhood Chain testnet, signed by `STRIKE_PAYER_KEY`, else the agent key, within `STRIKE_X402_MAX_SPEND` per run); the payment and its settlement transaction go into the record under `payments` ([log](../../docs/testnet-epochs/2026-10-03-x402.md)) |

`STRIKE_CHAIN_ID=46630` is v2 on Robinhood Chain testnet and `STRIKE_CHAIN_ID=421614` is v3 on Arbitrum Sepolia (the SDK's deployment map). v3 on Robinhood Chain testnet is reached with the SDK's address overrides (`STRIKE_EPOCH_MANAGER` and friends, listed in [the v3 log](../../docs/testnet-epochs/2026-09-30-v3.md#7-live-epoch-1-october)).

`--help` lists every option. `pnpm --filter @strike/agent-example market-open` prints whether the NYSE session is open at the chain's latest block (`marketOpen()` in the SDK).

## Specialists

A propose run is five stages in a fixed order ([`src/specialists/run.ts`](src/specialists/run.ts)). Each has its own inputs and tools, and its output is computed from them; Claude, with `--llm`, only chooses the plan, and its words are stored as narration.

| Stage          | Reads                                                                                                                                                                                                                                                                                      | Output and verdict                                                                                                                                                                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Market analyst | `StockOracle.status` and `feedConfig` (the price's age against `maxPriceAge`), `isMarketOpen` and the `MarketCalendar` (next open, last closes), the token's ERC-8056 multiplier fields, the sequencer feed, `EpochManager.underlyings` (sigma and its bounds), the mainnet Chainlink feed | A brief with six checks (session, feed status, freshness, corporate action, sequencer, sigma bounds), each with the measured value and the limit; realised volatility from the mainnet closing prints; inputs compared that should agree. Go, or a no-go with reason codes (`MARKET_CLOSED`, `FEED_STALE`, ...) |
| Risk analyst   | `risk_check` (the contract's `previewProposal`) for a ladder of target deltas; the risk engine contract's `greeks` and `scenarioLoss` (the EpochManager's Stylus pricer, else the deployment's `riskEngine`)                                                                               | A table: per rung the strike, the contract's verdict, yield, greeks, the vault's worst payout at -30% to +30%, break-even and the model probability of exercise (Black-Scholes N(d2)); rejections counted by reason                                                                                             |
| Strike planner | The table, and the profile (`default`, `conservative`) or Claude (read-only MCP tools, given the brief and the table)                                                                                                                                                                      | The rung chosen and why, with every rung it considered                                                                                                                                                                                                                                                          |
| Critic         | `risk_check` on the exact plan and the risk engine for its numbers                                                                                                                                                                                                                         | MODIFY inside the mandate (delta into the band, premium up to the floor, size down to the profile's share; before and after recorded, then the mandate check again), and five rules in priority order: P0 market, P1 mandate, P2 cushion, P3 drift, P4 yield. Any failure is a veto                             |
| Contract       | `propose_epoch`, after a preflight (the payload bound to the critic's proposal by a keccak256 digest, an approval at most 120 s old, no dry-run flag)                                                                                                                                      | Accepted or rejected on-chain; not run on a dry run or after a veto                                                                                                                                                                                                                                             |

The critic's cushion rule wants the break-even at least half a one-sigma move to expiry from spot (`sigma x sqrt(tenor)`; 0.75 for the `conservative` profile), and its stress loss is quoted with it. A veto on the mandate or the cushion gets one retry a rung further out of the money; any other veto, a no-go or no rung inside the mandate is a no-trade decision. It is written and anchored like a proposal, with `result.status` `not-sent` and `result.noTrade` naming the stage, the reasons and the codes. A stage that could not read its inputs is recorded as failed, the rest as not run, and the run stops with the record written. When the chain has no risk engine (the local devnet: anvil cannot run Stylus), the greeks and the stress are "not provided" and the critic does not veto for it.

Example from 3 October, a Saturday: on both v3 put vaults the market analyst said "market closed until Mon 5 Oct 13:30 UTC", a no-trade. With `--ignore-session` the rest ran: 8 rungs, 6 inside the mandate, the planner took 0.20 delta, and the critic passed all five rules. A fifth, with `--llm --planner claude-code`, had Claude choose the rung (0.20 delta, with its reasons as narration). The records are in [`docs/agent-log/dry-runs/`](../../docs/agent-log/dry-runs/).

## Claude plans the epoch (`--llm`)

With `--llm`, Claude reads the vault with the MCP server's read-only tools (`vault_state`, `risk_check`, `agent_stats`, `quote`), dry-runs candidates and hands back a target delta, a premium factor and its reasoning for depositors. It never gets a write tool: the agent code clamps the plan into the mandate, dry-runs it once more and proposes. Claude runs through one of two planners:

- **Claude API** (`--planner api`, [`src/llm.ts`](src/llm.ts)): the Anthropic SDK's tool runner, billed per token to `ANTHROPIC_API_KEY`.
- **Claude Code CLI** (`--planner claude-code`, [`src/claudeCode.ts`](src/claudeCode.ts)): `claude -p` on a Claude Pro or Max subscription, so no API key is needed. Log in once with `claude` (then `/login`), or, for CI and servers, run `claude setup-token` and set the long-lived token it prints as `CLAUDE_CODE_OAUTH_TOKEN`. Each run counts against the subscription's usage limits.

Without `--planner`, the agent uses the API when `ANTHROPIC_API_KEY` is set, else Claude Code when `claude` is on `PATH` (or `CLAUDE_CODE_OAUTH_TOKEN` is set), else the default strategy. The decision record names the planner (`Claude via API, model claude-opus-5` or `Claude via Claude Code CLI, model claude-opus-5`).

The Claude Code planner is locked down: the CLI runs in an empty temp directory with `--setting-sources ""` (no CLAUDE.md, settings or hooks), `--tools ""` (no Bash, Edit, Write or WebFetch), `--strict-mcp-config` with only the Strike server, `--allowedTools` set to the four `mcp__strike__*` planning tools and `--permission-mode dontAsk`, so anything else is denied. It starts its own Strike MCP server on the agent's chain and RPC with `STRIKE_MCP_READ_ONLY=1` (only the read tools are registered) and without the agent key; the CLI's environment has neither the key nor `ANTHROPIC_API_KEY`. The plan comes back as structured output (`--json-schema`, the same bounds as the API planner's `submit_plan`). A missing CLI, a missing login, a timeout (6 minutes), a refusal or an invalid answer falls back to the default strategy with the reason in the record.

```bash
# try it on the local devnet without sending anything (scripts/demo-local.sh shows the anvil + deploy steps)
STRIKE_CHAIN_ID=31337 STRIKE_RPC_URL=http://127.0.0.1:8545 STRIKE_AGENT_PRIVATE_KEY=0x... \
  pnpm --filter @strike/agent-example start -- --vault sTSLA-CC --llm --planner claude-code --dry-run
```

`STRIKE_CLAUDE_CODE_MODEL` changes the model (default `claude-opus-5`; e.g. `sonnet` uses less of the subscription), `CLAUDE_CODE_PATH` the CLI, and `STRIKE_PLANNER_MCP_URL` points Claude Code at a read-only HTTP MCP endpoint (such as `https://strike-options.vercel.app/api/mcp`, testnet) instead of a local server.

## Joining as a new agent (`--register`)

Any agent can join Strike on its own. With `--register` the example agent does it through the MCP server's `register_agent` and `create_vault` tools, with the key in `STRIKE_AGENT_PRIVATE_KEY` as the agent's owner and signer (it pays the bond, so it needs USDG; on testnets take some from `/app/faucet`):

```bash
# register + bond the minimum (50 USDG on the deployments), then create a TSLA cash-secured-put vault it runs
STRIKE_CHAIN_ID=31337 STRIKE_RPC_URL=http://127.0.0.1:8545 STRIKE_AGENT_PRIVATE_KEY=0x... \
  pnpm --filter @strike/agent-example start -- --register --bond 50 --create-vault TSLA:put
```

1. **Check** (`register_agent` with `dryRun`): the signer key has no agent yet, the wallet holds the bond, and the bond reaches `minBond`. It prints each check and the rules: at least `minBond` bonded to propose, `slashAmount` lost per rejected proposal, suspended at `maxStrikes`. A failed check stops the run before anything is sent.
2. **Register and bond** (`register_agent`): `AgentRegistry.register`, then an approve and `postBond`. `--bond <usdg>` sets the amount; the default is the minimum bond. Re-running is safe: a key that is already an agent is only topped up when it is below the minimum or `--bond` is given.
3. **Create a vault** (`--create-vault SYMBOL:call|put`, `create_vault` dry run then send): a covered-call or cash-secured-put vault on an allow-listed stock, run by this agent, with the default mandate (`|delta|` 0.10-0.35, premium at least 95% of fair value, tenor 1-8 days). The dry run shows the mandate and the protocol floors it must pass (premium at least 90% of fair value, tenor at most 35 days). You become the vault's curator.

The vault then needs deposits before it can sell; after that the usual loop applies: `--vault sTSLA-CSP-A2` proposes for it (the symbol ends with your agent id). Without `--create-vault`, the other way in is to ask an existing vault's curator to call `EpochManager.setVaultAgent(vault, yourAgentId)`. See [Join as a new agent](../../docs/STRIKE_SKILL.md#join-as-a-new-agent) in the skill file.

## Decision records (`--log`)

With `--log <dir>` the agent keeps its console output and also writes what it did and why: the date and chain, the vault and its mandate, the market inputs (the spot and sigma snapshotted when the epoch opened, or live values when no epoch runs), the target delta with the strategy's rule or Claude's own reasoning, the dry-run verdict, each transaction with an explorer link (Blockscout on 46630, Arbiscan on 421614), the result (accepted with its series, or rejected with the reason and the slash) and the agent's track record afterwards. A JSON copy with the same name sits next to the markdown for the app. The record also lists the alternatives the agent dry-ran, not only the strike it chose (see "Alternatives in the record" below). The directory is relative to where you run the command. A second run on the same day for the same vault gets a `-2` suffix, so no record is ever overwritten. With `--settle --log`, a series the keeper already settled this week is looked up on-chain (`EpochSettled`) and recorded instead of failing.

### Alternatives in the record

The risk analyst dry-runs a ladder of target deltas through the read-only `risk_check` (the contract's own `previewProposal`): every 0.05 across the vault's mandate band, both band edges, one 0.05 past each edge, and the profile's delta. The premium factor is the profile's (fair value with `--llm`), and the size is the largest the mandate allows, so the rungs compare like with like (a profile that offers less, such as `conservative`, still sends its smaller size, which the critic records as a MODIFY). The ladder runs before the planner, which chooses from it, so it is there for `--dry-run` too; a market no-go stops the run before it. With `--llm`, every `risk_check` Claude itself made while planning is recorded too, through both planners (the API tool loop, and the `tool_use` and `tool_result` events of Claude Code's stream).

Each one goes into `decision.candidates` in the JSON (and a section "Alternatives it dry-ran" in the markdown):

| Field                                                                     | Meaning                                                                                                                                         |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `source`                                                                  | `planner` (a call Claude made, in call order, with its arguments in `inputs`) or `ladder` (the agent's own sweep, by delta)                     |
| `targetDeltaBps`, `premiumBps`                                            | What was asked. `targetDeltaBps` is null when Claude passed an explicit strike                                                                  |
| `ok`, `reason`                                                            | The contract's verdict and `MandateGuard` reason (`None` when accepted)                                                                         |
| `strike`, `delta`, `fairValue`, `premium`, `yieldBps`, `size`, `capacity` | What the contract measured. `premium` is fair value times the premium factor, per option, in USD                                                |
| `chosen`                                                                  | True for every ladder rung at the chosen delta, and for the last accepted planner call that asked for exactly the chosen delta and premium      |
| `failedRule`                                                              | For a rejected candidate: `{ rule, measured, limit }`, e.g. `DeltaOutOfBand`, delta 0.3999 measured against a band of 0.10 to 0.35              |
| `explanation`                                                             | The risk check's plain-words text                                                                                                               |
| `error`                                                                   | Only on an entry whose dry run could not be read (`ok: false`, `reason: null`, no measured values). URLs in the message are replaced by `<url>` |

`decision.candidates` is part of the hashed JSON, so `--anchor` commits it with everything else. The field is optional: records written before it, or a run where nothing was dry-run, have no `candidates` key and keep their hash. The app's parser (`app/src/lib/agentLog.ts`) reads every field above (all optional, so older records parse as before); the vault page's "Why this strike" panel and the decision page `/app/decision/<chain>/<record>` show them, with `failedRule` as the measured value against its limit and error entries as "could not be read".

The records of the live testnet vaults are published in [docs/agent-log](../../docs/agent-log/).

### The pipeline in the record

A propose run adds these to `decision` in the JSON (and a "Specialists" and an "Alternatives to grade at settlement" section to the markdown). All are optional and inside the hashed JSON; records without them keep their hash.

| Field            | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pipeline`       | One entry per stage in the order they ran (a retry adds a second planner and critic with `attempt: 2`): `stage` (`market`, `risk`, `planner`, `critic`, `contract`), `verdict` (`pass`, `modify`, `fail`, `not-run`), `summary`, `inputs`, `output`, `sources` (MCP tools, contract reads with their address, SDK computations), `durationMs`, `by` (`rule`, `claude`, `contract`) and, when Claude wrote any, `narration` |
| `llm`            | With `--llm`: what the Claude call used, as the API or the Claude Code stream reported it: `planner` (`api` or `claude-code`), `model`, `calls`, `inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheCreationTokens`, `costUsd`, `durationMs` and `source`. The planner stage carries the same figures as `usage`. Rule-mode runs have neither                                                                         |
| `alternatives`   | The chosen strike, kept cash, half size, one rung nearer to spot and one farther, each with strike, size, premium, break-even, model probability of exercise and worst ±30% payout, and `taken` for what the agent did                                                                                                                                                                                                     |
| `confidence`     | `worthlessProbability`: the model odds that the chosen option expires worthless, with its basis. Computed, never self-reported                                                                                                                                                                                                                                                                                             |
| `contradictions` | Inputs that should agree, compared: the testnet mirror against the mainnet print, the pricer's sigma against realised volatility, the MCP server's spot against the oracle, and with `--llm` Claude's own dry run of its plan against the critic's                                                                                                                                                                         |

A value a stage could not get is `{ "provided": false, "reason": "..." }`, never a default. A dry-run record also has a top-level `run` (`dryRun`, `ignoreSession`, `note`).

**Claude's token use (`decision.llm`).** The agent writes down only what the source reported. With the API planner, `calls` is the number of Messages API responses and the token fields are the sums of their `usage` objects; the API reports no price, so `costUsd` is `{ "provided": false, "reason": "..." }`, and `durationMs` is the agent's own clock around the planning call. With the Claude Code planner, the figures come from the `result` message of the `stream-json` output: `usage` (cumulative over the run), `num_turns` as `calls`, `duration_ms` and `total_cost_usd` as `costUsd`. That cost is Claude Code's own estimate at list prices; a subscription is not billed per token, so read it as a size, not a charge. A field the source left out is `{ "provided": false, "reason": "..." }`, never 0, and a Claude Code run that ended without a result message records every figure that way. When Claude was called but gave no plan, the tokens it spent are still recorded and the rule planner chooses as before. The field is optional and hashed, so records without it keep their hash. The decision page shows it in the run line under the stage strip; for a record without the field it says the record does not carry token counts. The dry run [`2026-10-03-sTSLA-CSP-as-if-open-claude-dry-run-2`](../../docs/agent-log/dry-runs/2026-10-03-sTSLA-CSP-as-if-open-claude-dry-run-2.md) is a live one (Claude Code, v3 put vault on 46630): 10 calls, 8 input, 2,604 output, 57,383 cache-read and 23,371 cache-creation tokens, 0.3297 USD estimated, 44.4 s.

### Anchoring records on-chain (`--anchor`)

With `--log <dir> --anchor`, the agent also commits each record to the [DecisionLog](../../contracts/src/agents/DecisionLog.sol) contract (`decisionLog` in the SDK's deployments, or `STRIKE_DECISION_LOG`). It sends `DecisionLog.record(agentId, vault, epoch, recordHash, uri)` from `STRIKE_AGENT_PRIVATE_KEY`, which must be the agent's current signer in the AgentRegistry:

- `recordHash` is keccak256 of the JSON record, computed before the anchor is added: the published JSON without its `anchor` field and without the `DecisionLog.record` transaction. `verifyAnchoredRecord(json)` and `recordHash(record)` in [`src/anchor.ts`](src/anchor.ts) rebuild those bytes from a published file and check them.
- `uri` is the record's GitHub URL, `https://github.com/Prashant-thakur77/Strike/blob/main/docs/agent-log/<file>.json` (`STRIKE_RECORD_BASE_URL` changes the directory).
- `epoch` is the vault's `currentEpoch()` after the run, plus one when a propose run left the vault Idle (it was deciding about the next epoch).

The transaction goes into the record's transactions list and an "On-chain anchor" section. If anchoring fails, the record is still written, unanchored, and the error is printed. The weekly workflow runs with `--anchor`.

## Running it every week (GitHub Actions)

[`.github/workflows/agent.yml`](../../.github/workflows/agent.yml) runs the agent autonomously as agent #1 on every live deployment, one job per chain through [`scripts/weekly-agent.sh`](../../scripts/weekly-agent.sh): Robinhood Chain testnet v2 and v3 (46630, v3 through the `STRIKE_*` overrides from `46630-v3.json`, records in `docs/agent-log`) and Arbitrum Sepolia v3 (421614, records in `docs/agent-log/arbitrum-sepolia`). It commits the records and anchors each in its deployment's DecisionLog. Its switches below are on since 2 October; with the variable off every run is skipped, and with it on but no agent key each run stops at a notice ([the job table](../../docs/operations.md#weekly-agent-jobs-chains-and-switches)):

- **Monday 15:00 UTC** (11:00 New York in summer, 10:00 in winter): it checks the NYSE session with `marketOpen()` and skips the week cleanly on a holiday. Then it runs the specialists on both TSLA vaults of each deployment with `--log --anchor` (`keeper.yml` keeps the prices fresh) and proposes where the critic passes; a no-go or a veto is committed and anchored as a no-trade record, and a vault still selling its series is skipped with a notice. It adds `--llm` when `ANTHROPIC_API_KEY` (the API planner) or `CLAUDE_CODE_OAUTH_TOKEN` (the Claude Code planner; the job then installs Claude Code 2.1.263) is set.
- **Friday 21:15 UTC** (after the 16:00 New York close all year): `keeper.yml` has settled the expired series, and the agent runs `--settle --log` on each vault. It records the keeper's settlement, and settles itself only if nothing has yet; a vault whose settlement record of the day exists is skipped. A vault with nothing to settle yet is a notice with no record: before expiry the agent exits 0, and after expiry while the feed has no round at or after expiry it exits 75 ("try again later"). The keeper settles that series at the first print and then starts a settle run that records it. If GitHub drops either slot, the keeper's chain starts the workflow again ([operations.md](../../docs/operations.md#what-runs-where-during-judging-4-to-12-october)).
- One run goes at a time (concurrency group `strike-agent`), and it does not send from the keeper key. It commits new records as `github-actions[bot]` with the message `agent-log: weekly epoch <date> (<mode>, chain <id>)`, and only when something changed.
- When `AGENT2_PRIVATE_KEY` is set, a last job runs agent #2 on `sTSLA-CSP-A2` (46630 v2) the same way, with `--profile conservative` on Monday.

Switches the owner flips (repo Settings → Secrets and variables → Actions):

| Kind     | Name                      | Value                                                                                                                                                                                                                                                                         |
| -------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Secret   | `PRIVATE_KEY`             | Optional: the deployer key from `contracts/.env`, agent #1's signer on 46630 v2. Without it v2 is skipped with a notice (the deployer is every contract's admin, so it is safer kept out of GitHub)                                                                           |
| Secret   | `AGENT_SIGNER_KEY`        | `AGENT_SIGNER_KEY` from `contracts/.env`: agent #1's separate v3 signer (`0x4fd9…AC6f`) on 46630 v3 and 421614. Without it those deployments are skipped with a warning                                                                                                       |
| Secret   | `AGENT2_PRIVATE_KEY`      | Optional: agent #2's key; adds the agent #2 job                                                                                                                                                                                                                               |
| Variable | `AGENT_ENABLED`           | `true` turns the weekly runs on (anything else, or unset, keeps them off)                                                                                                                                                                                                     |
| Secret   | `ANTHROPIC_API_KEY`       | Optional. When set, Claude plans each epoch (`--llm`, model `claude-opus-5`); the mandate guard in the agent code still clamps its plan before the dry run                                                                                                                    |
| Secret   | `CLAUDE_CODE_OAUTH_TOKEN` | Optional, used when `ANTHROPIC_API_KEY` is not set. Run `claude setup-token` on a machine logged in to a Claude Pro/Max subscription and store the token it prints; Claude then plans each epoch through the Claude Code CLI, counted against the subscription's usage limits |

`workflow_dispatch` runs it by hand (mode `propose` or `settle`). If `main` is branch-protected, allow GitHub Actions to push, or the commit step fails.
