# Changelog

All notable changes to Strike. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/) (pre-1.0: a minor version may change contract interfaces). Deployed contracts are immutable; a contract change means a new deployment, listed under **Deployments**.

### Added

- RPC: Alchemy for every Strike process when `ALCHEMY_API_KEY` is set, with the public RPCs as the fallback ([D39](docs/decisions.md)). The app gets `POST /api/rpc/<chainId>` (46630, 421614, 4663; [`route.ts`](app/src/app/api/rpc/%5BchainId%5D/route.ts), core in [`lib/rpc/proxy.ts`](app/src/lib/rpc/proxy.ts)): the key stays in the server environment and goes to Alchemy in an `Authorization` header; 15 read methods only (no `eth_sendRawTransaction`; wallets send their own transactions), batches up to 100 calls, bodies up to 256 kB, a 30-second per-instance cache for `eth_call` and `eth_getLogs` pinned to a block (never `latest`), per-call fallback to the public RPC when Alchemy is down, rate-limits or refuses a call (the free tier's 10-block `eth_getLogs` limit), never past a revert, a 30-second skip for an upstream that timed out or refused the key, the key scrubbed from anything relayed, and no CORS headers. `GET` says which provider answers, shown as "RPC: Alchemy" or "RPC: public" in `/app/proof`'s live pricer card. Browsers read through it when the build saw the key (`NEXT_PUBLIC_STRIKE_RPC_PROXY`, set in `next.config.ts`; only the flag is inlined), with the direct RPC as their own fallback; wagmi's reads, the activity feed, the monitor and the playground use it, wallet writes do not. `/api/stats`, `/api/mcp` and `/api/option` read Alchemy directly from the server. The SDK adds `rpcUrlFor`, `rpcEndpointsFor`, `rpcTransportFor`, `transportFromEndpoints`, `redactRpcUrl` and `describeRpc` (Alchemy, then `STRIKE_RPC_URL`, then the public RPC, through viem's `fallback`; the key in a header so viem's error messages never carry it; a loopback `STRIKE_RPC_URL` is never replaced), used by the MCP server, the example agent (reads, anchors, its MCP subprocess, the Claude Code planner's config by reference) and the Telegram bot, which log the RPC without the key. [`scripts/rpc.sh`](scripts/rpc.sh) does the same for `cast` in the keeper and the weekly agent (checked with `eth_chainId`, the public RPC with a warning otherwise). CI's fork tests, `keeper.yml` and `agent.yml` use the optional `ALCHEMY_API_KEY` secret. Tests: 15 SDK unit tests (`sdk/test/rpc.test.ts`, mock fetch), MCP, bot and agent config tests, and Playwright [`rpc.spec.ts`](app/e2e/rpc.spec.ts) (the proxy core with a mock fetch: allowlist, batches, fallback, revert, timeout, cooldown, limits, cache, key scrubbing; the built route: provider, unknown chains, sends refused, 413, a live batch on each chain) and the proof page's indicator; no test needs a real key. [operations.md](docs/operations.md#rpc-alchemy) says where the key goes and how to check it.
- Infra: the Telegram bot on AWS as code ([`infra/aws`](infra/aws/README.md)). A CloudFormation template for one `t4g.nano` instance (Amazon Linux 2023 arm64, no SSH key, no inbound rule, outbound HTTPS only, IMDSv2 required, encrypted 8 GB gp3, CPU credits capped at the baseline), its own VPC, an IAM role limited to Session Manager, the bot's SSM parameters and its log group, and CloudWatch Logs (`/strike/telegram-bot`, 14 days). The token and the optional `ALCHEMY_API_KEY` stay in SSM SecureStrings and are read at each start into a root-only file on tmpfs; the bot runs as an unprivileged, sandboxed systemd service. `deploy-bot.sh` checks the login, stores the secrets without echoing them, refuses while a local bot is running, carries the local state file (subscribers, cursor) over and waits for the bot's startup line; `update-bot.sh` pulls and restarts over SSM Run Command; `destroy-bot.sh` can save the state first. About $8.29 a month in ap-southeast-1. Checked with cfn-lint, ShellCheck, `systemd-analyze verify` and a local test of the start path ([`instance-test.sh`](infra/aws/test/instance-test.sh)); not deployed yet.
